# Generic multi-build validation receipts — 2026-10-23

Runs produced with `generic/exploit_generic.py` (commit of this directory)
against local isolated targets on the `root@contabo` research VM. Every
target was network-isolated (loopback only). No third-party system was
contacted.

## php-8.4.26-run1/

Full chain against the calibrated `php:8.4.26-apache-bookworm` target
(pinned image digest, 1 prefork worker, `memory_limit=8M`,
`display_errors=Off`) using the offsets extracted by
`generic/libphp_offsets.py` from the pinned `libphp.so`
(`--validate-8426` confirms they equal the original hand-calibrated
values). This run closes the loop: every build in this receipt set,
including the reference one, goes through the auto-extraction path.
`RCE_OUTPUT_OBSERVED`, `uid=33(www-data)`.

## php-8.4.25-run1/ and php-8.4.25-run2/

Full three-stage chain against a fresh `php:8.4.25-apache-bookworm`
container (image digest `sha256:0629e7852d88a0939841973910d94157de7cd68e48acefac44546f8534b45d31`,
same ini profile as the calibrated 8.4.26 lab: 1 prefork worker,
`memory_limit=8M`, `display_errors=Off`, `session.save_path=/tmp/php2shell-sessions`).
The terminal offsets came exclusively from
`generic/profiles/php-8.4.25-amd64.json` generated by
`generic/libphp_offsets.py`; no other recalibration was performed.

Both runs ended with `status: RCE_OUTPUT_OBSERVED` and
`command_output: uid=33(www-data) gid=33(www-data) groups=33(www-data)`.
Run 1 additionally keeps the two disclosure cookies (`heap-cookie.bin`,
4000 bytes; `libphp-cookie.bin`, 128 bytes) as evidence of the phase 1 and
phase 2 `Set-Cookie` leaks.

## WordPress on PHP 8.4.25 and 8.4.20

The same WordPress 7.1.3 + SQLite Integration 3.1.1 stack was rebuilt on
`php:8.4.25-apache-bookworm` and `php:8.4.20-apache-bookworm` (only the base
image changed; the pinned libphp/module-list checks are 8.4.26-specific and
were dropped) and installed as `www-data`. The full chain then succeeded
with the same auto-extracted offset profiles as the minimal targets:

- WordPress/8.4.25: `RCE_OUTPUT_OBSERVED` (third cold-master attempt; the
  first two drew an unfavourable ASLR mapping, correctly reported by the
  client's `aslr_draw_favourable` check before phase 2);
- WordPress/8.4.20: `RCE_OUTPUT_OBSERVED` on the first attempt.

The complete console logs of both runs — including the `result.json` — are
preserved as the screenshots
`screenshots/rce-wordpress-php-8.4.25.png` and
`screenshots/rce-wordpress-php-8.4.20.png`; the `result.json` fields are
embedded in them.
